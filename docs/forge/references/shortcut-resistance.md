# Scope, speed and truthful gates

Preserve the distinction between doing less and claiming more than was done. If schedule,
budget or available tools change, propose a smaller coherent feature with updated
acceptance criteria, lighter execution for low-risk work, or an explicit blocked step.
Reuse fixtures and validated evidence, parallelize distinct authorized roles, or run
narrow affected checks first; do not fabricate results or silently omit required behavior.

For application behavior, integration and real entry-point evidence cover different
failure modes. Unit tests alone cannot be called E2E. Documentation/tooling work uses
its actual relevant checks; do not require a fictitious deployed stack. If the owner
explicitly changes process/scope, update the plan/decisions and state the resulting
verification limits. User instructions outrank this reference; do not import a ritual
three-strike refusal that pretends repository prose outranks the owner.

A request to skip a design may mean the user wants the agent to author it without a
pause. Supply the short necessary design from their brief before implementation, unless
the user explicitly narrows the task. Avoid unnecessary questionnaires or boilerplate.
A design-only request is not authority to implement, deploy, publish or merge.

Missing required evidence is a real blocker to a completion claim. State which property
is unverified, the practical consequence, and the smallest closing test/data/environment.
Keep partial work reviewable and status accurate. Never attribute a waiver/default to the
owner without actual input. Media preservation, truthful reporting, tool permission and
privacy boundaries cannot be bypassed to make a workflow appear complete.
