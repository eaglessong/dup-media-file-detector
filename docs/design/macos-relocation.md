# macOS relocation

Status: Implemented and reviewed; delivered through PR8, unmerged.

## Problem and reconnaissance
Linux-only `move_fs` relies on capabilities, ext4/statx/ioctls and mountinfo. Journal uses Linux procfs. Existing strict Linux fixture tests cannot simply be enabled on Darwin. Five PROSPECT instruments were executed by two read-only scouts; native coordinator probes on macOS27.2.1 arm64/APFS confirm directory fsync, F_FULLFSYNC, no-replace link and physical F_GETPATH_NOFIRMLINK. `/dev/fd/DIR/child` SQLite failed; Python has no os xattr API here. Darwin SDK mount.h/fcntl.h establish ABI; use ctypes native descriptor xattr APIs.

## Requirements and non-goals
R1: Ordinary-user 64-bit macOS APFS relocation, same and distinct-device volumes, using existing CLI.
R2: Exact main-stream bytes only; refuse resource forks on keeper/victim/destination at preflight and final checks. Other metadata may be omitted. Expose policy in JSONL header.
R3: Preserve external-root/no-symlink/no-overwrite/fresh-proof/exclusive-access/scratch/dry-run safeguards, deterministic keeper and relative mapping.
R4: Durable external journal and verified destination before unlink; fail closed on copy/sync/journal/mutation failures and cancellation.
R5: Strict Linux behavior and read-only scan defaults unchanged.
Non-goals: HFS+, network volumes, copying metadata, automatic recovery, real media operations, merging.

## Approach and alternatives
Add isolated Darwin adapter dispatched by move_fs; reuse byte proof/SQLite plan/transfer. Fixed Darwin statfs64 ctypes layout validates APFS and enumerates mounts. Resolve nearest existing descriptor via physical F_GETPATH_NOFIRMLINK plus missing suffix for physical containment, including Data-volume firmlinks. Reject nested mounts and cross-device traversal within source. Keep identity pins and exclusive namespace requirement; concurrent uncooperative writers remain unsupported.

Resource-fork detection uses native flistxattr, failing on unreadable metadata; do not copy other metadata. Metadata token identifies data-only policy; scanner signatures and repeated exact byte proofs still detect data changes. Reject flagged regular files rather than remove locked/unsupported entries. Destination copies mode0600, directory0700; inherited ACLs may apply. No time/permission fidelity promised.

Use ordinary SQLite path only on Darwin, revalidate operation-directory pins around journal writes; require SQLite fullfsync ON and synchronous FULL. Full-sync regular copied files before and after publication, fsync directories, no fallback after errors. This improves flush requests, not a physical power-loss guarantee.

Memory stays bounded by existing CHUNK streaming and SQLite cursors; plan scales on disk. Cancellation leaves recoverable extra staged/published copies and journal; no batch rollback. Exit/error codes remain unchanged. No uploads/absolute private-path diagnostics.

## PR8 F1 follow-up — permission preflight (AGENT, before implementation)

Review5951648652 identifies static readable-but-unwritable directories passing the
shared global preflight. Existing authorization is sufficient; no new USER policy is
needed. Reuse earlier full reconnaissance; scoped five-instrument scouts confirm the
gap and normal-user fixture requirements. Native coordinator probes on APFS confirm
Darwin `faccessat` accepts extended modes with effective credentials and rejects0555,
ACL delete denial and ACL add-file denial while allowing unrelated add-directory rights.
Installed SDK and Apple public XNU vfs_syscalls.c access1/faccessat_internal establish
_DELETE_OK parent-aware ACL/sticky authorization, rather than manual mode parsing.

R6: Before any destination/journal mutation, check each victim's deletion permission,
each mapped destination parent's creation/cleanup capability (or nearest ancestor's
subdirectory creation if missing), and external journal parent's subdirectory creation.
Use descriptor-relative native effective-credential checks; no probe files. Mac uses
_DELETE_OK on victim, _EXECUTE_OK plus _WRITE_OK/_RMFILE_OK for staging in an existing
parent, or _APPEND_OK for a missing suffix. Linux uses effective access with its existing
privileged/strict adapter gates. Existing namespace pins and execution checks remain.
Errors source_permission_denied, destination_permission_denied or journal_permission_denied
produce exit1/incomplete with zero moves. Paths remain root-relative (journal uses '.').

Conservative boundary: new descendants can inherit ACLs not represented by access on
the existing parent. Reject creation parents with file/directory-inheritable ACL entries
as permission_inheritance_unsupported; allow non-inheritable ACLs when native action
checks permit. This explicit AGENT fail-closed restriction avoids simulating ACL inheritance
or mutating dry-run trees. Revisit when faithful inheritance support is requested.

Acceptance/tests: both integration and shipped CLI cover a later0555 victim after a
writable group, existing destination0555, missing destination suffix, source ACL delete
denial, destination add-file/add-directory denial, external journal parent denial,
inheritable ACL refusal, and positive non-inheritable ACL/sticky-owner controls. Dry-run has no journal argument, so journal permissions apply only to execution. Negative
cases must yield zero moves, identical source/destination manifests and no new operation
directory/staging. Real foreign-owned sticky fixture uses privileged setup only, then
runs application under ordinary user; required CI stage fails if setup absent. Local
lack of passwordless setup is an explicit skip/gap, closed by actual macOS CI. Synthetic
data only; no real media. Test-data plan ADEQUATE, native foreign-sticky run pending CI.
