# macOS relocation

Status: Accepted for implementation.

## Problem and reconnaissance
Linux-only `move_fs` relies on capabilities, ext4/statx/ioctls and mountinfo. Journal uses Linux procfs. Existing strict Linux fixture tests cannot simply be enabled on Darwin. Five PROSPECT instruments were executed by two read-only scouts; native coordinator probes on macOS27.2.1 arm64/APFS confirm directory fsync, F_FULLFSYNC, no-replace link and physical F_GETPATH_NOFIRMLINK. `/dev/fd/DIR/child` SQLite failed; Python has no os xattr API here. Darwin SDK mount.h/fcntl.h establish ABI; use ctypes native descriptor xattr APIs.

## Requirements and non-goals
R1: Ordinary-user 64-bit macOS APFS relocation, same and distinct-device volumes, using existing CLI.
R2: Exact main-stream bytes only; refuse resource forks on keeper/victim/destination at preflight and final checks. Other metadata may be omitted. Expose policy in JSONL header.
R3: Preserve external-root/no-symlink/no-overwrite/fresh-proof/exclusive-access/scratch/dry-run safeguards, deterministic keeper and relative mapping.
R4: Durable external journal and verified destination before unlink; fail closed on copy/sync/journal/mutation failures and cancellation.
R5: Strict Linux behavior and read-only scan defaults unchanged.
Non-goals: HFS+, network volumes, copying metadata, automatic recovery, real media operations, merging.

## Approach and alternatives
Add isolated Darwin adapter dispatched by move_fs; reuse byte proof/SQLite plan/transfer. Fixed Darwin statfs64 ctypes layout validates APFS and enumerates mounts. Resolve nearest existing descriptor via physical F_GETPATH_NOFIRMLINK plus missing suffix for physical containment, including Data-volume firmlinks. Reject nested mounts and cross-device traversal within source. Keep identity pins and exclusive namespace requirement; concurrent uncooperative writers remain unsupported.

Resource-fork detection uses native flistxattr, failing on unreadable metadata; do not copy other metadata. Metadata token identifies data-only policy; scanner signatures and repeated exact byte proofs still detect data changes. Reject flagged regular files rather than remove locked/unsupported entries. Destination copies mode0600, directory0700; inherited ACLs may apply. No time/permission fidelity promised.

Use ordinary SQLite path only on Darwin, revalidate operation-directory pins around journal writes; require SQLite fullfsync ON and synchronous FULL. Full-sync regular copied files before and after publication, fsync directories, no fallback after errors. This improves flush requests, not a physical power-loss guarantee.

Memory stays bounded by existing CHUNK streaming and SQLite cursors; plan scales on disk. Cancellation leaves recoverable extra staged/published copies and journal; no batch rollback. Exit/error codes remain unchanged. No uploads/absolute private-path diagnostics.

## Acceptance and test plan
| Requirement | Integration | Actual entry-point E2E | Demo |
|---|---|---|---|
| R1 | Native APFS and disk-image distinct st_dev | `-m dup_media` cross-volume | nested duplicate relocated |
| R2 | Real forks on keeper/victim and late insertion; xattr/mode/time loss | fork rejection and header policy | policy explicit |
| R3 | dry-run, symlink/physical aliases, collision, hardlinks, zero/Unicode | dry-run then move | originals unchanged by plan |
| R4 | injected copy/sync/journal errors, late mutations | SIGINT/SIGKILL boundaries and journal states | source retained until verified |
| R5 | existing Linux CI and portable scan suites | existing entry-point tests | scan unchanged |

Fixtures: original generated bytes with media extensions, native xattr/fork syscalls; disposable APFS image for cross-device tests. Test-data gate ADEQUATE for implementation plan: native APFS observed; image execution remains required completion evidence in local or macOS CI. Add mandatory macOS CI; missing cross-volume fixture fails required platform suite, not a silent skip. No benchmark performance promise; bounded synthetic measurements only.
